# Электронный журнал студентов

Учебное приложение на Flask, Jinja2, JavaScript и SQLite. Для запуска нужен Python 3.11 или новее и современный браузер с включённым JavaScript.

## Запуск в Debian Linux

Установите системные пакеты, если их ещё нет.

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip sqlite3 unzip
```

Распакуйте архив и выполните команды в терминале.

```bash
cd starter
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python prepare_db.py
python check_db.py --baseline
python check_rollback.py
python app.py
```

Откройте [http://127.0.0.1:5000/](http://127.0.0.1:5000/). Остановить сервер можно через Ctrl+C. При следующем запуске активируйте окружение и выполните `python app.py`.

## Что работает

| Раздел | Действия |
| --- | --- |
| Группы | Список с количеством студентов, добавление, переименование и удаление пустой группы |
| Предметы | Добавление, переименование и удаление предмета без оценок. Новый предмет появляется во всех группах журнала |
| Студенты | Поиск по имени, фильтр по группе, добавление, редактирование, перевод и удаление с подтверждением |
| Журнал | Выбор группы, просмотр всех её студентов, установка, изменение и удаление оценки |
| Отчёты | Показатели групп, студенты без оценок и студенты хотя бы с одной двойкой |

## Архитектура

У каждого из пяти разделов есть свой каталог в `features/`. Это вертикальные срезы. В каждом вместе лежат серверный код, HTML и JavaScript одного раздела.

| Файл | За что отвечает |
| --- | --- |
| `__init__.py` | Создаёт Blueprint и импортирует маршруты. `app.py` регистрирует все пять Blueprint |
| `pages.py` | Возвращает HTML-шаблон через Jinja2 |
| `api.py` | Читает HTTP-параметры или JSON, вызывает сервис и возвращает ответ |
| `service.py` | Проверяет правила, открывает соединение и управляет транзакцией |
| `repo.py` | Выполняет SQL с параметрами через переданное соединение |
| `templates/<раздел>/index.html` | Задаёт форму и структуру таблицы, наследует общий `base.html` |
| `static/<раздел>.js` | Обрабатывает события, вызывает API и обновляет DOM |

В `db.py` включаются внешние ключи для каждого соединения. Общие шаблоны шапки и подвала лежат в `templates/partials/`. Общие помощники для HTTP и интерфейса лежат в `static/js/`.

## JavaScript на примере оценки

1. **Открытие страницы.** Шаблон журнала подключает `journal.js` как модуль. `start()` запрашивает `GET /api/groups` и заполняет выпадающий список. Затем `load()` отправляет `GET /api/journal?group_id=1` для выбранной группы. Ответ содержит группу, студентов, предметы и выставленные оценки.
2. **Построение таблицы.** `render()` создаёт строки из студентов и столбцы из предметов. `Map` хранит оценки по ключу вида `10:1`. Это ID студента и ID предмета. Если ключа нет, в ячейке появляется «—». Для двойки добавляется CSS-класс `failing`. Текст записывается через `textContent`.
3. **Выбор ячейки.** Один обработчик `click` на теле таблицы через `closest()` находит кнопку нажатой ячейки. Этот приём называется делегированием событий. Он работает и после перерисовки строк. Из атрибутов `data-student-id` и `data-subject-id` код получает нужную пару и открывает форму.
4. **Сохранение.** Обработчик `submit` вызывает `event.preventDefault()` и отправляет JSON через `saveGrade()`. Например, `{"student_id":10,"subject_id":1,"mark":3}` отправляется методом `POST` на `/api/journal/grades`. Значение из `select` преобразуется в число через `Number()`.
5. **Ответ сервера.** `requestJSON()` в `static/js/api.js` использует `fetch()`. `await` ждёт ответ внутри асинхронной функции. Если ответ имеет статус 400 или 404, `fetch()` всё равно возвращает объект `Response`, поэтому помощник проверяет `response.ok`. После `DELETE` статус 204 означает пустое тело и помощник сразу возвращает `null`.
6. **Обновление экрана.** Пока идёт запрос, `busy(true)` блокирует элементы управления. После успеха форма закрывается, выполняется новый `GET` и таблица перерисовывается без перезагрузки страницы. При ошибке `catch` показывает сообщение, форма остаётся открытой и сохраняет выбранное значение. `finally` снимает блокировку.

В `students.js` поиск и фильтр сразу применяются к уже загруженному массиву через `filter()`. При сохранении студента отправляется отдельный запрос. В `reports.js` изменение списка отчётов отправляет `GET` с параметром `kind` и строит таблицу из ответа.

## Что происходит на сервере

Оценки хранятся в таблице `grades`. Ограничение `UNIQUE(student_id, subject_id)` разрешает одну строку на пару. Сервис принимает целые оценки от 2 до 5. В одной транзакции он ищет существующую строку и выбирает `INSERT` или `UPDATE`. `BEGIN IMMEDIATE` получает право записи до проверки, поэтому два одновременных запроса не попытаются создать две строки для одной пары.

При переводе меняется `students.group_id`. ID студента остаётся прежним, поэтому строки оценок продолжают ссылаться на него. При удалении сервис в одном блоке `with con` удаляет оценки, затем студента. Если между этими командами возникает исключение, оно выходит из блока и SQLite откатывает первый `DELETE`. Репозиторий выполняет SQL, а фиксацией и откатом управляет сервис.

В отчёте групп `LEFT JOIN` сохраняет пустые группы, `COUNT(DISTINCT s.id)` считает каждого студента один раз, а `AVG(gr.mark)` берёт среднее по всем выставленным оценкам. В двух других отчётах `HAVING COUNT(gr.id) = 0` находит студентов без оценок, а `HAVING MIN(gr.mark) = 2` находит студентов с двойкой. Для пустой группы средний балл равен `NULL`, в интерфейсе виден «—».

## Как показать на защите

1. Откройте **Журнал**, выберите **БЭИ2301**, затем в инструментах разработчика откройте **Network** и выберите фильтр **Fetch/XHR**. В исходной базе у студента с ID 10 нет оценок. Найти его можно в массиве `students` ответа журнала.
2. Поставьте этому студенту 3 по Python, затем измените на 5. Покажите тело `POST`, ответ `200` и следующий `GET`. Сравните `item.id` в ответах на оба `POST`. ID оценки останется тем же. Удалите оценку и покажите ответ `204` и «—» в ячейке.
3. Переведите студента с выставленными оценками в другую группу через страницу **Студенты**. Откройте новую группу в журнале и покажите, что оценки сохранились.
4. Добавьте пустую группу и откройте отчёт **Показатели групп**. Для неё будут 0 студентов, 0 оценок и «—». Переключите два оставшихся отчёта.
5. Выполните `python check_rollback.py`. Скрипт копирует БД, вызывает учебную ошибку между двумя удалениями и сравнивает все строки четырёх таблиц до и после ошибки. Затем на той же копии он проверяет обычное удаление.

## Исходная база и восстановление

`prepare_db.py` создаёт `instance/journal.db` из `data/schema.sql` и `data/seed.sql`. Исходные данные содержат 3 группы, 60 студентов, 3 предмета и 162 оценки. Шесть студентов без оценок имеют ID 10, 20, 30, 40, 50 и 60.

Для восстановления остановите сервер и выполните `python prepare_db.py`, затем `python check_db.py --baseline`. Восстановление заменяет текущие учебные данные исходными. Команда `python check_db.py` без флага проверяет связи и выводит количества для изменённой базы.

## Контракты API

| Запрос | Успешный ответ |
| --- | --- |
| `GET /api/groups`, `GET /api/subjects`, `GET /api/students` | `200` и массив `items`. Для студентов можно передать `group_id` и `q` |
| `POST /api/groups`, `POST /api/subjects`, `POST /api/students` | `201` и объект `item`. Группы и предметы принимают `name`. Студенты принимают `name`, `group_id` и необязательный `email` |
| `POST /api/groups/ID`, `POST /api/subjects/ID`, `POST /api/students/ID` | `200` и обновлённый `item` |
| `DELETE` по адресу записи справочника или студента | `204` с пустым телом |
| `GET /api/journal?group_id=1` | `200` и поля `group`, `students`, `subjects`, `grades` |
| `POST /api/journal/grades` | `200` и `item` с итоговой оценкой |
| `DELETE /api/journal/grades/STUDENT_ID/SUBJECT_ID` | `204`, в том числе при повторном удалении оценки существующей пары |
| `GET /api/reports?kind=groups` | `200` и поля `kind`, `items`. Другие значения `kind` — `no_grades` и `failing` |

Ответ `400` с полем `error` сообщает об ошибке данных или запрете удаления по зависимости. `404` означает, что запись или маршрут отсутствует.

Историю лабораторных можно посмотреть командой `git log --oneline` в распакованном проекте.
